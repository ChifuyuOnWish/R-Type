    Settings¶

    Open the menu¶

    Press F1 or Escape, press Start on the selected controller, or click the Settings button. The menu also remains available on connection status pages. Escape opens or closes Settings; use the window close button or Quit application to exit.

    Use a window of at least 640 x 360.

    Control Effect
    Up / Down Select a row
    Left / Right Change a value
    Enter or Space Activate the selected row
    Escape or F1 Back, or cancel key capture
    Mouse wheel Move the selection
    Click a row Activate it
    Click its left/right arrow Decrease/increase a value

    Menu controls stay fixed when gameplay controls are rebound.

    Available settings¶

    Setting Choices Default
    Volume 0 to 100%, steps of 5% 50%
    Mute On / Off Off
    Background motion On / Off On
    UI text size 100%, 125%, 150% 100%
    Scene tint Off, Red, Green, Blue, Amber Off
    Tint opacity 0 to 50%, steps of 5% 15%
    Keyboard bindings Movement and fire Arrows and Space
    Gamepad On / Off On
    Controller Slots 1 to 4 1
    Stick dead zone 5 to 80%, steps of 5% 20%
    Left stick movement On / Off On
    Gamepad bindings Movement and fire buttons D-pad and South face button

    The tint is a full-window colored rectangle blended over the game scene. It covers the background, sprites and scene text. UI rectangles, overlay text, Settings and connection status pages remain un-tinted. It requires no image asset or shader. It is a visual preference; it is not a color-vision correction or a simulation of a color-vision deficiency.

    Text size scales menu text, connection status text and the scene/overlay text submitted by the client. The GUI scales the font size and character spacing; overlay positions remain in window pixels. When RenderScene::worldSize is set, sprite destinations, origins and scene text are scaled to fit that world in the window; overlay text and Settings keep their screen-space layout. The client must choose suitable HUD positions and wrapping for larger text.

    Disabling background motion freezes the starfield. It does not pause gameplay, stop network updates or hide entities.

    Rebind keys¶

    Activate a Key row, then press the new key. The activating press is not captured as the replacement. If another action uses that key, the two bindings are exchanged. Press Left on a Key row to remove its binding. Escape or F1 cancels capture.

    Supported keys are arrows, Space, A to Z, Enter, left/right Control and left/right Shift. Escape and F1 are reserved for menu navigation.

    Configure a controller¶

    Use Start / Menu to open Settings. D-pad or left stick moves the selection, Left/Right edits a value, South (A/Cross) activates a row and East (B/Circle) goes back. These menu controls stay fixed when gameplay buttons are rebound.

    Choose a controller slot, then Apply and save before configuring that device. The status line describes the active device, not an unapplied draft selection. Activate a Pad row and press a new controller button. The activating press is not captured as its own replacement. Conflicting gameplay bindings are swapped. Left clears a Pad binding. Start, Escape or F1 cancels capture; East can be assigned as a gameplay button during capture.

    The left stick always uses the movement actions when enabled; Pad bindings add buttons to those actions. Disable left-stick movement for a button-only setup. Disabling Gamepad or choosing an unconnected slot requires keyboard/mouse to restore a usable input device. No reconnect or rebind operation should produce an unintended shot: release the controls before resuming gameplay.

    Apply and cancel¶

    Changes stay in a draft until Apply and save is selected. The menu previews its text size immediately. Apply updates the running GUI and writes preferences to disk; the menu stays open and reports the result. Back, Escape or F1 discards changes made since the last Apply.

    Restore defaults resets the draft. Apply it to keep the defaults.

    Opening Settings releases gameplay actions. On startup, after API rebinding, and after closing Settings, all sampled gameplay keys must be released before input resumes. This avoids an activation key becoming an unintended shot.

    The client must continue calling pollActions() and render() every frame while Settings is open. The menu does not pause the client or a multiplayer session.

    Persistence¶

    Settings are loaded when the GUI opens and saved only by Apply and save.

    Platform Default file
    Linux with absolute XDG_CONFIG_HOME $XDG_CONFIG_HOME/rtype/settings.conf
    Linux otherwise $HOME/.config/rtype/settings.conf
    Windows %APPDATA%/RType/settings.conf

    An explicit GuiConfig::settingsPath replaces the default location. The client exposes it through --settings path. If no default directory is available, settings still apply for the session and saving reports an error.

    Existing version 1 files without gamepad entries remain valid and use default gamepad settings. The version 1 text format stores volume, mute, background motion, text scale, tint mode/opacity, five keyboard bindings and gamepad preferences. Missing optional values use defaults, and unknown entries are ignored. Unsupported versions, duplicate entries, invalid values or files larger than 16 KiB are rejected without partially applying settings.

    Saving writes a temporary sibling file before replacing the previous file. A write error leaves the existing destination in place where replacement failed; details are logged to the terminal. If saving fails, the new values still apply for the current session. Invalid files are not overwritten until the user explicitly selects Apply and save.

    Explicit API calls to setKeyBindings() or setAudioSettings() before opening take precedence over the corresponding saved preferences. API updates are not automatically written to disk.

    Local checks¶

    cmake --preset release
cmake --build --preset release
ctest --preset release
./r-type_client

    To use a separate test file on Linux:

    ./r-type_client --settings /tmp/rtype-settings-check.conf

    Without --connect, the client shows an empty background with Settings available. To check movement against the authoritative server, use two terminals:

    ./r-type_server 4242

    ./r-type_client --connect 127.0.0.1:4242 --name Player

    Only server entities are rendered. No local fixture ships, projectiles or scheduled enemy removals are created. The client opens at 1920 x 1080. Its 1920 x 1080 world fits the current window with uniform scaling and centered placement, preserving its aspect ratio.

    1. Open and close Settings with F1, Escape and the mouse.
    2. Rebind an action, apply, close Settings and verify movement in the connected game.
    3. Assign an already used key and check that the bindings are exchanged.
    4. Hold Fire, open the menu and verify that gameplay actions are released. After closing, release the key before testing Fire again.
    5. While connected, fire and check server-confirmed shot sounds. Change volume and mute, apply, restart and verify the saved values. Mute and --no-audio must suppress sound without preventing movement or rendering.
    6. Disable background motion and check that the stars stop scrolling.
    7. Apply each tint and change its opacity. The scene changes color while Settings and overlay text remain readable.
    8. Set text size to 150% and resize. Check labels, footer messages and HUD text.
    9. Apply settings, restart and check that they are restored.
    10. Change a setting then Back. Reopen and check that the change was discarded.
    11. Connect to an unavailable port, wait for failure and verify Settings remains reachable.

    Automated tests cover draft edits, binding swaps, persistence/error paths, menu transitions, text scaling and tint drawing order using fake native boundaries. These tests do not validate actual window rendering or audio hardware. Record manual results on supported platforms before merging.

    Gamepad verification¶

    Automated checks cover action transitions, dead zones, reconnect safety, keyboard coexistence, menu navigation, button capture, persistence and older keyboard-only settings. Native devices are replaced by injected states.

    Manual verification is still required on both platforms. Record the controller model, firmware if known, wired/Bluetooth connection, OS and result. Check every row, save/restart, focus changes, disconnect while firing, reconnect with a held button, and navigation on connection status pages. An empty result is pending, not a pass.

    Included controller layouts¶

    Controller layouts are loaded from bundled data at startup. The included project mapping proposes support for the wired Elite 2 revision 0517 reported in testing. It reuses the known wired layout and remains pending hardware verification. Players do not need to create a mapping file for this entry. The entry is included in the bundled database, loaded automatically without a user-created mapping file.
